# 인증 및 토큰 정책

| 항목 | 내용 |
|------|------|
| Access Token 유효시간 | 30분. HTTP `Authorization: Bearer {token}` 헤더로 전달. 토큰 종류 claim `typ=access`인 토큰만 API 인증에 사용된다. |
| Refresh Token 유효시간 | 7일. HttpOnly Cookie로 저장 (XSS 방어). 토큰 종류 claim은 `typ=refresh`이며, `Authorization: Bearer`로 제출해도 인증되지 않는다 (`POST /api/auth/refresh`와 로그아웃 시 세션 식별에만 사용). |
| 자동 재발급 | Axios interceptor에서 401 응답 감지 → `POST /api/auth/refresh` 호출. 성공 시 원래 요청 재시도. 실패 시 로그인 페이지 이동. |
| 로그아웃 | `POST /api/auth/logout` → 현재 기기의 Access Token 블랙리스트 등록 + 현재 기기 세션의 Refresh Token 삭제 + 클라이언트 Cookie 삭제. 다른 기기 세션은 유지된다 (아래 "다중 기기 로그인 정책" 참고). |
| 비로그인 접근 | 인증 필요 페이지 접근 시 로그인 모달 표시. 로그인 완료 후 원래 URL로 redirect. React Router의 PrivateRoute 컴포넌트로 구현. |
| 소셜 로그인 플로우 | `GET /api/auth/login/{provider}` → OAuth 리다이렉트 → `GET /api/auth/callback/{provider}` → Refresh Token 쿠키 설정 → `isNewUser` 파라미터로 분기. provider: `google`\|`kakao` |

## 다중 기기 로그인 정책

> 2026-09-27 확정 (토큰 종류 구분·재사용 감지 포함).

| 항목 | 내용 |
|------|------|
| 동시 로그인 | 허용. 로그인할 때마다 기기(브라우저) 단위의 독립 세션이 생성된다. 세션은 Refresh Token의 세션 식별자(`jti`)로 구분한다. |
| 최대 세션 수 | 사용자당 5개. 6번째 로그인 시 가장 오래 전에 생성된 세션부터 제거한다. 제거된 기기는 Access Token 만료(최대 30분) 후 재발급이 거부되어 재로그인이 필요하다. |
| Refresh Token 회전 | `POST /api/auth/refresh` 호출마다 새 Refresh Token을 발급하고 기존 값은 즉시 무효화한다. 회전 시 세션 식별자는 유지된다. 검증과 교체는 원자적으로 처리한다. 이전 Refresh Token 유예 구간은 두지 않는다. |
| 재사용 감지 | 이미 회전되어 무효화된 Refresh Token이 다시 제출되면 탈취로 간주해 해당 세션을 즉시 폐기하고 `REFRESH_TOKEN_INVALID`를 반환한다. 해당 기기는 재로그인이 필요하며, 다른 기기 세션은 영향받지 않는다. 같은 Refresh Token으로 동시에 요청하는 경우도 재사용으로 판정되므로 클라이언트는 refresh 호출을 직렬화해야 한다. |
| 로그아웃 | 현재 기기의 세션만 종료한다. Refresh Token Cookie가 없거나 유효하지 않아도 로그아웃은 성공한다(해당 세션은 TTL 만료로 정리). |
| 회원 탈퇴 | 해당 사용자의 모든 세션을 삭제한다. |
| 계정 정지 | 정지 처리 시 해당 사용자의 모든 세션(Refresh Token)을 삭제한다. 이미 발급된 Access Token은 만료(최대 30분)까지 유효할 수 있다. |
| 전체 기기 로그아웃 | 제공하지 않는다. |

## PENDING 역할 정책

소셜 로그인 결과에 따라 아래와 같이 분기한다.

| 상황 | 처리 |
|------|------|
| 신규 소셜 로그인 | PENDING 역할 발급. `isNewUser=true` 로 FE 리다이렉트. |
| 탈퇴 후 재로그인 | 종전 계정은 재활성화하지 않고 새 계정으로 가입한다(PENDING 역할 발급, `isNewUser=true` 로 FE 리다이렉트). 종전 계정의 정보는 승계되지 않는다. |
| 정지 중 탈퇴 후 재로그인 | 보관 중인 소셜 로그인 식별자 해시와 일치하면 가입을 거부한다(재가입 제한 에러, 코드명은 BE 구현 시 확정). 아래 "회원 탈퇴 및 재가입 제한" 참고. |
| 기존 사용자 로그인 | USER/ADMIN 역할 유지. `isNewUser=false` 로 FE 리다이렉트. |
| 정지(SUSPENDED) 계정 로그인 시도 | 정지 종료 시각이 지났으면 로그인 시 자동 해제하고 정상 로그인한다. 정지 중이면 OAuth2 인증 단계(앱은 토큰 로그인)에서 차단, `USER_SUSPENDED` 에러 발생(정지 기간·사유 포함). 로그인 불가. |

PENDING 역할 사용자는 `POST /api/auth/register` (회원가입 완료) 호출 전까지 일반 기능 접근 불가.
회원가입 완료 후 USER 역할로 승격되며 USER 역할의 Access Token을 즉시 발급한다.

## 회원 정지 정책

> 2026-10-29 확정. 근거: 이용약관 제7조. 조치별 사유·기간 기준은 운영정책으로 정한다.

| 항목 | 내용 |
|------|------|
| 정지 주체 | 관리자가 신고를 처리하면서 작성자를 정지하거나 회원 관리에서 단독으로 정지·해제한다(ADM-05·ADM-13). 이미 정지 중인 회원을 다시 정지하면 새 기간·사유로 덮어쓴다. |
| 정지 기간 | 7일, 30일, 영구. 종료 시각은 정지 시각 + 기간(초 단위, 초 미만 버림). 일시 정지는 종료 시각이 지난 뒤 다음 로그인 때 자동 해제된다. |
| 통지 | 정지 처리 시 이메일이 있는 회원에게 정지 통지 메일(정지 기간, 사유, 상세 사유, 7일 이내 이의신청 안내, 운영정책 링크 `https://www.comingg.com/operation-policy`)을 보내고, 이후 로그인·refresh·쓰기 시도 시 `USER_SUSPENDED` 응답(정지 기간·사유 포함)으로 알린다. 정지 통지 메일은 정보성 메일로 마케팅 수신 동의와 무관하게 발송한다. |
| 이의신청 | 통지일로부터 7일 이내 이메일로 신청(이용약관 제7조 제4항). |
| 세션 | 정지 시 모든 기기 세션(Refresh Token)을 삭제한다. 정지 직후 남은 Access Token(최대 30분)으로 읽기는 허용하고 쓰기·수정·삭제는 아래 "정지 회원 쓰기 차단"으로 막는다. |
| 정지 회원 쓰기 차단 | 정지 회원은 비회원과 같이 콘텐츠 조회만 할 수 있다. 게시글·댓글 작성·수정·삭제, 추천·좋아요와 그 취소, 신고 접수, 별점 등록·수정·삭제, 아티스트 팔로우·언팔로우, 캘린더 추가·삭제, 문의 등록, 닉네임·마케팅 동의 변경은 모두 `USER_SUSPENDED`(403). 로그아웃은 허용한다. 정지 종료 시각이 지난 회원은 허용한다. |
| 정지 중 탈퇴 | 본인 탈퇴(`DELETE /api/auth/withdraw`)는 `USER_SUSPENDED`로 거부한다(남은 Access Token으로 탈퇴해 정지를 피하는 것 방지). 개인정보 보호책임자 이메일로 요청한다. 가입한 소셜 계정의 이메일 주소에서 온 요청만 관리자 대리 탈퇴(`DELETE /api/admin/users/{id}`)로 처리한다. |
| 정책 변경 고지 | 정지 회원도 약관 적용 대상이므로 정책 변경 고지 메일을 받는다(ADM-11). |

### `USER_SUSPENDED` 응답 형식

`USER_SUSPENDED`(403)만 공통 에러 형식(`code`, `message`)에 아래 필드를 더한다. 다른 에러는 기존 형식을 유지한다.

| 필드 | 타입 | 설명 |
|------|------|------|
| `suspendedUntil` | String? | 정지 종료 시각. 오프셋 없는 KST `yyyy-MM-ddTHH:mm:ss`. 영구 정지면 `null` |
| `reason` | String | 정지 사유 코드(`ReportReason`) |

```json
{
  "code": "USER_SUSPENDED",
  "message": "정지된 계정입니다.",
  "suspendedUntil": "2026-11-05T12:00:00",
  "reason": "SPAM"
}
```

적용 경로: 앱 토큰 로그인, `POST /api/auth/refresh`(웹·앱), 정지 회원 쓰기 API, 정지 회원 본인 탈퇴. 웹 OAuth2 로그인은 JSON 대신 리다이렉트 쿼리로 전달한다(`api/auth.md` `GET /api/auth/callback/{provider}` 참고).

## 회원 탈퇴 및 재가입 제한

> 2026-10-29 확정. 근거: 개인정보처리방침 제3조, 이용약관 제4조 제3항·제10조. 식별자 보관과 재가입 차단은 시행일(2026-12-02) 이후 탈퇴부터 적용한다.

| 항목 | 내용 |
|------|------|
| 즉시 삭제 | 이메일, 닉네임, 출생연도, 마케팅 동의, 별점, 팔로우, 캘린더, 문의. user 행은 개인정보를 모두 비우고(provider_id는 `withdrawn:{id}`, 정지 정보도 삭제) 탈퇴 시각(`withdrawn_at`)과 빈 번호로만 남긴다. provider_id가 바뀌므로 같은 소셜 계정으로 다시 로그인하면 새 PENDING 계정이 생성된다(종전 계정 재활성화 없음). |
| 게시글·댓글 | 삭제하지 않고 작성자를 "탈퇴 회원"으로 표시한다. 탈퇴 회원의 user id 등 작성자 식별값은 API 응답에 노출하지 않는다. |
| Kakao | 탈퇴 시 Admin 키로 연결 끊기(unlink) API를 호출한다. 탈퇴 커밋 후 호출하며, 실패해도 탈퇴는 유지하고 재시도하지 않는다. |
| Apple | 탈퇴 커밋 후 Apple 토큰 revoke를 요청한다. 실패해도 탈퇴는 유지한다. |
| 재요청 | 이미 탈퇴한 회원의 탈퇴 요청(본인·관리자)은 `USER_NOT_FOUND`(404). |
| 남은 Access Token | 탈퇴 시 요청에 쓴 Access Token만 블랙리스트에 등록되므로 다른 기기의 Access Token은 만료(최대 30분)까지 남는다. 이 토큰으로 쓰기·수정·삭제("정지 회원 쓰기 차단"과 같은 범위, 회원가입 완료 포함)를 요청하면 `USER_NOT_FOUND`(404)로 거부해 파기한 개인정보가 다시 저장되지 않게 한다. |
| 식별자 보관 | 별도 테이블에 provider+provider_id의 HMAC 해시, 만료 시각, 정지 중 탈퇴 여부만 저장한다(user id 미저장, 원본 미저장). |
| 보관 기간 | 일반 탈퇴: 탈퇴일로부터 30일. 정지 중 탈퇴: 탈퇴일로부터 30일과 정지 종료일 중 늦은 날. 영구 정지 중 탈퇴: 탈퇴일로부터 1년. 만료 시 스케줄러로 지체 없이 파기한다. |
| 보관 기간 내 재가입 | 일반 탈퇴 회원은 새 계정으로 가입할 수 있다. 정지 중 탈퇴한 회원은 가입을 거부한다. |
